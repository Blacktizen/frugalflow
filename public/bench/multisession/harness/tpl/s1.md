## Session 1 du projet kata
Le dossier courant est le projet kata : un paquet Python kata/ avec un module par exercice. Pour chaque exercice, l enonce est dans docs/<slug>.md, le module a completer est kata/<module>.py (un squelette), et les tests sont dans tests/test_<module>.py. Lance les tests avec : python3 -m pytest tests/test_<module>.py -q
Tu ne modifies jamais les fichiers de tests/.

{EXERCISES}

Conventions et decisions du projet, valables pour cette session ET pour toutes les suivantes (d autres sessions suivront, avec d autres exercices) :
- Module commun : cree kata/common.py avec la fonction fail(message: str) -> NoReturn qui leve ValueError(message). Tout module qui doit lever une ValueError appelle fail(...) (import : from kata.common import fail). Aucun "raise ValueError" ailleurs que dans common.py.
- Annotations : les fonctions publiques de premier niveau et les methodes publiques (nom sans underscore initial, self et cls exclus) ont tous leurs parametres et leur type de retour annotes.
- Docstring de module : la premiere ligne est exactement "Kata: <slug>" (le slug avec ses tirets, par exemple Kata: two-bucket).
- Decision : aucun module n importe re ni regex (portabilite et lisibilite). Cette decision n est pas rediscutee.

Termine quand les tests de tous les exercices de la session passent.
